# Трекинг: комплексные и целочисленные фильтры для IQ-потоков

## Цель
Реализовать полноценную линейку IQ-фильтров для:
- комплексных потоков
- целочисленных потоков формата HackRF One (interleaved int8 I/Q)
- целочисленных потоков формата USRP B210 (interleaved int16 little-endian I/Q)

С обязательным повторением существующей методики:
- расчёт коэффициентов (как в текущих FIR/IIR/семействах Butterworth/Chebyshev/Elliptic)
- структура API фильтров
- система модульных тестов и проверок устойчивости

## Ключевой принцип внедрения
Каждый этап должен давать сразу используемый результат (не ждать окончания всей программы работ).

## Область покрытия
- FIR
- IIR (включая SOS там, где применимо)
- Билдеры/спецификации для расчёта коэффициентов
- Потоковые API (Span/Stream + async)
- Набор тестов (корректность, стабильность, совместимость форматов)

## Соглашения по форматам
- HackRF One: interleaved int8, порядок байт I,Q,I,Q...
- USRP B210: interleaved int16 LE, порядок I,Q,I,Q...
- Для целочисленных API обязательны:
  - saturating clamp
  - явно документированная политика округления
  - контроль переполнений и формата входа

### Этап 6: Полная тестовая матрица и регрессия
Статус: Planned

Результат этапа:
- Единая система модульных тестов для всех представлений сигнала

Подсистемы тестирования:
- Unit: корректность Process/Reset/State
- Golden vectors: фиксированные входы/выходы
- Property-based: инварианты (линейность, нулевая реакция, boundedness)
- Stability/long-run: длинные последовательности, дрейф и overflow
- Format tests: interleaved/endianness/odd-length/partial-read
- Cross-check: complex vs double(I/Q), int vs quantized reference

Критерии готовности:
- Покрытие критичных веток не ниже целевого порога
- Отсутствие флаки-тестов
- Отдельные профили тестов: fast/extended

Используемость после этапа:
- Надёжная база для дальнейшего развития и рефакторинга

## Технические риски и меры
- Риск: расхождение результатов между complex и int ветками
  - Мера: единый reference pipeline + golden vectors
- Риск: нестабильность IIR высоких порядков
  - Мера: обязательный SOS путь и long-run тесты
- Риск: overhead от конвертаций
  - Мера: Span/in-place API и профилирование hot path
- Риск: ошибки формата USRP LE
  - Мера: отдельный набор тестов на endian/знак/границы
