# Трекинг улучшений для MathCore.HackRF (сессия кодового агента)

## Метаданные сессии
- Репозиторий-источник наблюдений: MathCore.DSP
- Целевая библиотека для доработок: MathCore.HackRF
- Контекст задачи: реализация end-to-end FM RX конвейера (HackRF One -> DSP -> NAudio)
- Статус документа: рабочий трекинг для переноса в проект MathCore.HackRF

## Принцип отбора предложений
- В документ включены только улучшения, которые реально уменьшат объем кода, повысят выразительность API или упростят потоковую обработку RX/TX.
- Предложения привязаны к практическим проблемам, замеченным во время реализации FM-демо.
- Идеи «ради улучшения» без прикладной пользы не включались.

## Наблюдаемые проблемы в текущем использовании API
1. Инициализация RX-сценария многословна: ручной `Initialize/Shutdown`, создание `Device`, набор параметров, запуск сессии, ручная синхронизация завершения.
2. Для типового кейса захвата блока IQ нужен дополнительный инфраструктурный код (буфер, счетчики, событие, таймаут).
3. Сигнатура блочного callback удобна для производительности, но менее удобна для прикладных сценариев и обучения.
4. Потоковая обработка хорошо покрыта для базовой RX-сессии, но не хватает high-level DSL для сборки конвейеров RX/TX и их композиции.
5. Нет симметричного «богатого» набора high-level инструментов для TX-сценариев, аналогичных удобству RX-пайплайна.
6. Не хватает встроенных средств диагностики потока на уровне библиотеки устройства (быстрые метрики, мониторинг очереди, удобный health snapshot).

## Предложения по улучшению

### HACKRF-001. High-level RX Capture API для сокращения шаблонного кода
- Идея: добавить метод уровня `CaptureIqAsync(...)` с возвратом готового блока `byte[]` или `Memory<byte>`.
- Минимальный интерфейс: параметры частоты, sample rate, gain, duration или samples count, timeout, cancellation token.
- Польза: резко сокращает шаблонный код захвата в прикладных приложениях и туториалах.
- Приоритет: высокий.
- Риск: низкий.
- Критерий готовности: типовой сценарий «захватить 1 сек IQ» выполняется 1-2 строками кода.

### HACKRF-002. Конфигурационный объект профиля устройства
- Идея: добавить неизменяемый профиль `RxProfile`/`TxProfile` и метод `ApplyProfile(...)`.
- Содержимое профиля: частота, sample rate, bandwidth, LNA/VGA, antenna power, queue policy.
- Польза: код становится более выразительным и повторно используемым.
- Приоритет: высокий.
- Риск: низкий.
- Критерий готовности: настройки устройства передаются одним объектом и легко логируются.

### HACKRF-003. Builder/Fluent API для запуска сессии
- Идея: добавить fluent-конструктор вроде `device.Rx().WithProfile(...).WithQueue(...).OnError(...).Start(...)`.
- Польза: более читаемый код запуска SDR-сценариев, меньше «технического шума».
- Приоритет: средний.
- Риск: средний.
- Критерий готовности: код запуска RX/TX сессии читается как декларация конвейера.

### HACKRF-004. Async-stream API поверх callback (IAsyncEnumerable)
- Идея: дать адаптер `GetRxBlocksAsync(...)` с `IAsyncEnumerable<RxBlock>`.
- Польза: естественная интеграция с современным async/await кодом и backpressure-подходом.
- Приоритет: высокий.
- Риск: средний.
- Критерий готовности: блоки RX можно обрабатывать через `await foreach` без ручной синхронизации.

### HACKRF-005. Расширенный набор TX-инструментов
- Идея: добавить high-level TX pipeline: очередь кадров, pacing, underrun strategy presets, удобные producer adapters.
- Польза: RX и TX становятся симметричными по удобству API, проще строить ретрансляцию и генераторы.
- Приоритет: высокий.
- Риск: средний.
- Критерий готовности: типовой TX-сценарий запускается без ручного управления низкоуровневыми деталями.

### HACKRF-006. Готовые «канальные» адаптеры для RX->TX relay
- Идея: добавить встроенные адаптеры relay с настраиваемой буферизацией, jitter control и телеметрией.
- Польза: быстрее собирать устойчивые realtime-связки между устройствами.
- Приоритет: средний.
- Риск: средний.
- Критерий готовности: relay-сценарий стартует через один конфиг и предоставляет метрики качества.

### HACKRF-007. Встроенный health snapshot и диагностические счетчики
- Идея: расширить статистику сессий единым `GetHealthSnapshot()`.
- Метрики: drop/underrun rate, queue utilization, callback latency p50/p95/p99, throughput, last errors.
- Польза: упрощает отладку и эксплуатацию без внешней телеметрии.
- Приоритет: высокий.
- Риск: низкий.
- Критерий готовности: пользователь получает компактный технический снимок состояния сессии одной командой.

### HACKRF-008. Удобные безопасные preset-политики
- Идея: добавить предустановки (`RxPreset.BroadcastFm`, `RxPreset.WidebandScan` и т.д.) с валидными диапазонами параметров.
- Польза: проще старт для студентов и новых пользователей, меньше конфигурационных ошибок.
- Приоритет: средний.
- Риск: низкий.
- Критерий готовности: можно запустить FM RX одной preset-конфигурацией и точечными override.

### HACKRF-009. Улучшение XML-документации high-level API
- Идея: для каждого нового high-level метода добавить полноценный блок `remarks` с рабочим примером.
- Польза: снижается порог входа, быстрее интеграция в прикладные проекты.
- Приоритет: высокий.
- Риск: низкий.
- Критерий готовности: ключевые методы имеют примеры end-to-end (RX capture, async stream, TX send).

## Что не предлагается специально
- Низкоуровневые изменения драйвера без явной прикладной выгоды в пользовательском API.
- Добавление сложных абстракций, если они не сокращают код и не улучшают читаемость типовых сценариев.
